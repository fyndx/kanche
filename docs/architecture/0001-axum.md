# Use Axum for the HTTP service

Kanche starts as a single Axum service on Tokio. PostgreSQL is the planned
durable store for identities, sessions, and authorization state.

Axum's Tower integration lets us exercise routes, middleware, status codes,
headers, and cookies in process. When the integration is implemented, browser
tests must cover origin policies, redirects, and the selected flow over real
HTTP. Measure sign-in and refresh latency with storage and cryptography in the loop.

Keep HTTP request/response types at the transport boundary. Identity, sessions,
and authorization should use application types so Kanche's first-party clients
can evolve without coupling domain logic to a transport representation.
